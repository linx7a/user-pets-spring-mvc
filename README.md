# user-pets-spring-mvc

REST API на Spring Boot MVC для управления пользователями и их питомцами. Учебный проект: HTTP-слой на Spring MVC, валидация входных данных, единый формат ошибок и тесты на MockMvc. Данные хранятся в памяти (`HashMap`), база данных не нужна.

## Возможности

- создание, получение, обновление и удаление пользователей;
- добавление и удаление питомцев пользователя;
- валидация входных данных с понятными сообщениями об ошибках;
- единый формат ответа при ошибках (400, 404, 500).

## Технологии

- Java 17
- Spring Boot (Spring MVC, Jakarta Validation)
- Maven
- JUnit 6, MockMvc, AssertJ

## Запуск

```bash
./mvnw spring-boot:run     # Windows: mvnw.cmd spring-boot:run
./mvnw test                # запуск тестов
```

Приложение стартует на `http://localhost:8080`.

## API

### Пользователи — `/api/users`

| Метод | Путь | Описание | Успех |
|-------|------|----------|-------|
| POST | `/api/users` | Создать пользователя | 201 |
| GET | `/api/users/{id}` | Получить пользователя вместе с питомцами | 200 |
| PUT | `/api/users/{id}` | Обновить пользователя (питомцы сохраняются) | 200 |
| DELETE | `/api/users/{id}` | Удалить пользователя | 204 |

### Питомцы — `/api/pets`

| Метод | Путь | Описание | Успех |
|-------|------|----------|-------|
| POST | `/api/pets` | Создать питомца для пользователя (`userId`) | 201 |
| DELETE | `/api/pets/{id}` | Удалить питомца | 204 |

### Правила

- `id` в теле запроса передавать нельзя: он назначается сервером.
- Питомец всегда привязан к существующему владельцу. Передать его другому владельцу нельзя.
- При обновлении пользователя список питомцев не меняется.

## Валидация

| Поле | Правило |
|------|---------|
| `id` | должно быть `null` (не передаётся) |
| `name` | не пустое |
| `email` | не пустое, формат адреса электронной почты |
| `age` | обязательное, не меньше 0 |
| `userId` (питомец) | обязательное |

## Формат ошибок

Все ошибки возвращаются в одном виде:

```json
{
  "message": "Ошибка валидации запроса",
  "detailedMessage": "name: не должно быть пустым",
  "dateTime": "2026-11-13T21:50:51.5610834"
}
```

| Код | `message` | Когда |
|-----|-----------|-------|
| 400 | Ошибка валидации запроса | данные не прошли валидацию |
| 404 | Сущность не найдена | пользователь или питомец не существует |
| 500 | Ошибка на сервере | непредвиденная ошибка |

## Примеры работы

**1. Создать пользователя** — `POST /api/users`

```json
{ "name": "Рон Уизли", "email": "ron@burrow.uk", "age": 17 }
```

Ответ `201`:

```json
{ "id": 1, "name": "Рон Уизли", "email": "ron@burrow.uk", "age": 17, "pets": [] }
```

**2. Создать питомцев** — `POST /api/pets`

```json
{ "name": "Короста", "userId": 1 }
```

Ответ `201`:

```json
{ "id": 1, "name": "Короста", "userId": 1 }
```

Второй питомец (`Сычик`) создаётся так же и получает `id` 2.

**3. Обновить пользователя** — `PUT /api/users/1`

```json
{ "name": "Рон Уизли (аврор)", "email": "ron@ministry.uk", "age": 19 }
```

Ответ `200`: данные изменились, оба питомца на месте.

```json
{
  "id": 1,
  "name": "Рон Уизли (аврор)",
  "email": "ron@ministry.uk",
  "age": 19,
  "pets": [
    { "id": 1, "name": "Короста", "userId": 1 },
    { "id": 2, "name": "Сычик", "userId": 1 }
  ]
}
```

**4. Удалить питомца** — `DELETE /api/pets/1` → `204`

Проверка владельца, `GET /api/users/1`: в списке остался только `Сычик`.

```json
{
  "id": 1,
  "name": "Рон Уизли (аврор)",
  "email": "ron@ministry.uk",
  "age": 19,
  "pets": [
    { "id": 2, "name": "Сычик", "userId": 1 }
  ]
}
```

**5. Ошибка валидации** — `POST /api/users`

```json
{ "name": "", "email": "не-сова", "age": -5 }
```

Ответ `400`:

```json
{
  "message": "Ошибка валидации запроса",
  "detailedMessage": "age: должно быть не меньше 0, name: не должно быть пустым, email: должно иметь формат адреса электронной почты",
  "dateTime": "2026-11-13T21:50:51.5610834"
}
```

**6. Владелец не найден** — `POST /api/pets`

```json
{ "name": "Живоглот", "userId": 666 }
```

Ответ `404`:

```json
{
  "message": "Сущность не найдена",
  "detailedMessage": "No found user by id=666",
  "dateTime": "2026-11-13T21:51:28.1665005"
}
```
